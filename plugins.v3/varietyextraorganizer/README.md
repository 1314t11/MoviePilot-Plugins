# 综艺加更整理（VarietyExtraOrganizer）

MoviePilot V3 插件。把国产综艺的「加更 / 加更 PLUS / 加更 Extra」文件硬链接进媒体库，
并按 `SxxEyy` 规范命名，让飞牛、Emby、Jellyfin 能正常识别和刮削。**源文件不动。**

- 插件 ID：`VarietyExtraOrganizer`
- 最低版本要求：MoviePilot `>= 3.0.0`
- 数据安全：只读源目录、只新建硬链接，不修改、不移动、不删除任何源文件

---

## 使用前提（必读）

装好插件后，先到 MoviePilot **设置 → 目录设置 → 屏蔽词**（文件整理屏蔽词）新增一条：

```
加更
```

这里是**正则**规则，写这两个汉字就够了，不用加 `.*`、不用引号。作用是让 MoviePilot 在整理/转移时
跳过文件名含「加更」的条目——否则主程序会先把加更文件当成正片处理走（重命名、移动到媒体库），
源目录里就没有可操作的文件了，插件也就无从下手。

顺便确认一下：

- **设置 → 目录设置 → 媒体库目录**：插件配置里的「媒体库目录」建议填这里已配置的综艺目录，
  插件放进去的文件才能被正常识别和刮削；
- **设置 → 词表 → 自定义识别词**：这一项与此插件无关，不用动。如果之前加过 `加更` 的屏蔽词，
  保留也不影响（它只影响识别文本，不影响整理）。

插件详情页会自动检查这一项：读的是 `TransferExcludeWords`（目录设置里的屏蔽词列表），
用一条真实样例名去试匹配。没配会在顶部显示橙色「前置条件未满足」，配好后变绿；改完刷新详情页即可，不用重装。

## 1. 这个插件解决什么问题

国产综艺（每周正片之外还发「加更」的那类）常见「加更」「加更 PLUS」内容，
源站命名通常是这样的：

```
示例综艺.加更.DemoShow.S05E01.Plus.2025.1080p.WEB-DL.mkv
示例综艺.加更.DemoShow.S04E14.Extra.2024.1080p.WEB-DL.mkv
```

问题出在两处：

1. `S05E01.Plus` 里的 `E01` 是**期号**，不是 TMDB 剧集编号；
2. 「加更」在 TMDB / 豆瓣等数据源里根本没有对应条目。

结果就是 MoviePilot 识别不到、Emby 刮削出一堆「未知剧集」，或者干脆不入库。

插件做的事很简单：把这些文件按季末续号重新编号，硬链接到媒体库目录，命名成标准
`SxxEyy` 格式，媒体库就会当成正常剧集收录。

| | 之前 | 之后 |
|---|---|---|
| 源目录 | `...S05E01.Plus...mkv` | 原样保留，一个字节都不动 |
| 媒体库 | 无（识别失败） | `示例综艺 - S05E25 - 第 02 集加更.mkv` |
| Emby | 未知剧集 / 不入库 | 正常收录进 Season 5 |

## 2. 命名规则

输出文件名格式：

```
剧名 - SxxEyy - 第 ZZ 集加更.ext
```

| 占位 | 取值方式 | 说明 |
|---|---|---|
| `剧名` | 由「剧名映射」或源目录名解析 | 如 `示例综艺` |
| `Sxx` | 源目录名里的季号 | 目录名 `.S05.` → `S05` |
| `Eyy` | **该季正片最大集号 + 加更序号** | 加更排到季末续号，不抢占正片集号 |
| `ZZ` | **源文件期号 × 2** | 第 1 期上 = 第 1 集，第 1 期下 = 第 2 集，故第 N 期加更 = 第 2N 集 |

为什么 `ZZ = 期号 × 2`：一期综艺通常分上下两集播出，加更对应的是「第 N 期」，
所以第 N 期加更在视觉上对应第 `2N` 集。这个数字只写在文件名的中文部分里，
方便你在媒体库里一眼认出来源，真正决定排序的仍是 `SxxEyy`。

举例，某季正片已入库到 `S05E24`，源目录里有三个加更文件：

| 源文件 | 源内期号 | 生成的文件名 |
|---|---|---|
| `...S05E01.Plus...mkv` | 1 | `示例综艺 - S05E25 - 第 02 集加更.mkv` |
| `...S05E02.Plus...mkv` | 2 | `示例综艺 - S05E26 - 第 04 集加更.mkv` |
| `...S05E03.Extra...mkv` | 3 | `示例综艺 - S05E27 - 第 06 集加更.mkv` |

## 3. 工作流程

每次执行按下面的顺序跑一遍，全程只读源目录：

1. **遍历源目录的一级子目录**，目录名里必须能匹配 `.S<数字>.`（如 `示例综艺.S05.2025`），
   匹配不到的直接跳过；
2. **筛选加更文件**：文件名同时包含「加更」并且包含 `.Extra` 或 `.Plus`；
3. **解析剧名和年份**：先查剧名映射（子串匹配），没有再取目录名里第一段中文；
   年份优先用媒体库里已存在的 `(YYYY)` 目录名，其次用源目录名里的年份；
4. **确定目标季目录**：`<媒体库目录>/<剧名> (<年份>)/Season <季号>/`；
5. **读取正片最大集号**：扫描目标季目录里已有的文件（跳过含「加更」的），
   取 `SxxEyy` 里最大的 `yy`；如果一集正片都没有，本季跳过并在日志里提示「无正片」；
6. **按源内期号升序硬链接**：`new_ep = 最大集号 + 序号`，目标文件已存在则跳过（幂等）；
7. **汇总日志**：`综艺加更整理：本次共硬链接 N 个加更文件`。

`os.link` 是硬链接，等同同一份数据多一个目录项：删掉媒体库里的那个文件，源文件仍在；
修改其中一个，另一个看到的内容也变（本来就是一个 inode）。

## 4. 目录要求

### 4.1 源目录（必须是这个结构）

```
/vol2/Movie/MP观影数据/电视剧/综艺/          ← 插件里填这个
├── 示例综艺.S05.2025/                     ← 一级：剧名.S季.年份
│   ├── 示例综艺.S05E01.2025.1080p.mkv      ← 正片（用来确定最大集号）
│   ├── 示例综艺.S05E02.2025.1080p.mkv
│   ├── 示例综艺.加更...S05E01.Plus.2025.mkv ← 加更（含「加更」+ .Plus/.Extra）
│   └── 示例综艺.加更...S05E02.Plus.2025.mkv
└── 示例综艺B.S03.2025/
    ├── 示例综艺B.S03E01.2025.1080p.mkv
    └── 示例综艺B.加更...S03E05.Extra.2025.mkv
```

要求：

- 季目录名必须含 `.S<数字>.`，`Season 05`、`第五季` 这类命名**不会**被识别；
- 源文件必须同时满足「文件名含『加更』」和「含 `.Plus` 或 `.Extra`」，只满足一个不动；
- 同一季的正片必须在同一个季目录里，插件靠它们计算 `max_ep`。

### 4.2 媒体库目录

```
/vol2/Movie/综合Link/电视剧/综艺/            ← 插件里填这个
└── 示例综艺 (2020)/                        ← 已存在则复用，不存在则新建
    └── Season 5/
        ├── 示例综艺 - S05E01.mkv            ← 你原来的正片
        └── 示例综艺 - S05E25 - 第 02 集加更.mkv ← 插件生成的
```

> 目标路径是 `<媒体库>/<剧名> (<年份>)/Season <季号>/`，年份取媒体库里已有目录的年份；
> 找不到已有目录时才用源目录名里的年份。

## 5. 安装

### 5.1 从插件市场安装（推荐）

1. MoviePilot → 插件 → 插件市场 → 右上角「插件市场设置」；
2. 在「插件仓库地址」里加入：
   `https://github.com/1314t11/MoviePilot-Plugins`（多个地址用英文逗号分隔）；
3. 保存后点「同步插件源」/刷新；
4. 在市场里搜「综艺加更」→ 安装。

索引有 30 分钟缓存，刷新后没出现就等一会儿或重启容器。
也可以用环境变量配置：

```bash
PLUGIN_MARKET=https://github.com/jxxghp/MoviePilot-Plugins,https://github.com/1314t11/MoviePilot-Plugins
```

拉取 GitHub 失败时，配 `GITHUB_PROXY`（加速站）或 `GITHUB_TOKEN`（避免限流）。

## 6. 配置项

| 配置 | 必填 | 默认 | 说明 |
|---|---|---|---|
| 启用插件 | — | 关 | 打开后按「扫描间隔」定时执行 |
| 立即运行一次 | — | 关 | 保存配置时立刻跑一轮，跑完自动复位，适合首次验证 |
| 扫描间隔(分钟) | — | `60` | 定时扫描周期；填 `0` 会被强制按 1 分钟处理 |
| 综艺源目录 | 是 | 空 | **容器内路径**，综艺源根目录，如 `/vol2/Movie/MP观影数据/电视剧/综艺` |
| 媒体库目录 | 是 | 空 | **容器内路径**，媒体库综艺根目录，如 `/vol2/Movie/综合Link/电视剧/综艺` |
| 剧名映射 | 否 | 空 | 每行一条 `源目录关键字=显示剧名`，用于目录名和剧名不一致的情况 |

### 剧名映射怎么用

源目录名经常带一堆后缀，比如 `示例综艺.S05.2025.WEB-DL.1080p`，默认解析会取第一段中文
（`示例综艺`）——大多数情况够用。当目录名解析错、或者你想统一显示名时再加映射：

```
示例综艺=示例综艺
示例综艺B=示例综艺B 完整版
示例综艺C=示例综艺C
```

规则：**子串匹配，自上而下第一条命中生效**，等号左边是目录名里出现的关键字，
右边是媒体库里的剧名（要和已有剧集目录名对得上，否则会新建一个目录）。

### 完整配置示例

| 配置项 | 值 |
|---|---|
| 启用插件 | ✅ |
| 扫描间隔 | `120` |
| 综艺源目录 | `/vol2/Movie/MP观影数据/电视剧/综艺` |
| 媒体库目录 | `/vol2/Movie/综合Link/电视剧/综艺` |
| 剧名映射 | `示例综艺=示例综艺`<br>`示例综艺B=示例综艺B 完整版` |

## 7. 使用流程

1. **先让正片入库**。插件靠目标季目录里已有的正片计算 `max_ep`，没有正片会跳过该季；
2. 填好两个目录 → 打开「立即运行一次」→ 保存；
3. 点开插件详情页看执行结果——页面顶部是状态卡和词表检查，下面是最近 12 条运行日志：

```
11-09 17:26:42 [INFO] 插件已启动，扫描间隔 120 分钟
11-09 17:27:03 [INFO] 示例综艺.加更.DemoShow.S05E01.Plus.2025.1080p.mkv -> 示例综艺 - S05E25 - 第 02 集加更.mkv
11-09 17:27:03 [INFO] 扫描完成：1 个季目录，新增 2 个链接，跳过 0 个已存在，失败 0 个（用时 0.1s）
```

4. 进媒体库确认文件在 `<剧名> (年份)/Season N/` 下，触发一次媒体库扫描；
5. 确认没问题后再打开「启用插件」，交给定时任务。

**关于日志**：插件同时往两个地方写日志——MoviePilot 主日志（`综艺加更整理：...`）和插件自己的运行记录。
详情页读的是后者，最多保留 40 条、展示最近 12 条，重启容器不丢；想看更早的记录去主日志里搜「综艺加更整理」。

**不会重复劳动**：目标文件已存在就跳过，所以反复跑、改间隔跑都安全。

## 8. 常见问题

**Q：详情页顶部一直提示「前置条件未满足：缺少屏蔽词“加更”」？**
去 MoviePilot「设置 → 目录设置 → 屏蔽词」新增一条 `加更` 并保存，然后刷新详情页。
检查是实时读取这项配置的，不需要重装插件或重启。注意这里要加在**目录设置的屏蔽词**，
不是「词表 → 自定义识别词」——后者只影响识别文本，不影响整理。

**Q：详情页日志是空的？**
说明还没跑过。到「配置」页勾选「立即运行一次」并保存，回来刷新就能看到结果。

**Q：日志提示「解析不到集号，跳过」？**
插件需要知道这一季已经排到第几集，才能把加更接在后面。它会在两个地方找 `SxxEyy`：
源目录里的正片文件、媒体库里 `Season N` 下的文件，取两者最大值。两个地方都没有，就会跳过，
日志里会打出「源目录 X 个文件、媒体库 Y 个文件」和目标路径，照这三个线索查：

1. **媒体库目录填错了**：日志末尾的「目标路径」如果不是你媒体库里那部剧的真实路径，
   说明「媒体库目录」这一项填的不是正片所在目录；
2. **库内文件名不带 SxxEyy**：比如重命名规则是 `剧名 - 第 N 期`，插件认不出来。
   这时只要源目录里还留着正片（带 `SxxEyy`），插件会自动改用源目录的集号；
3. **剧名对不上**：媒体库里那部剧的目录名不含解析出的剧名（日志里的 `S05` 前面那个词），
   加一条「剧名映射」让它对上。

**Q：报「硬链接失败：Invalid cross-device link」？**
源目录和媒体库目录不在同一个文件系统（不同硬盘、不同存储池、/vol2 与 /vol3）。
硬链接不能跨文件系统，这是操作系统限制。解决办法：把媒体库目录换到同一块盘，
或者手动改成软链接/复制（插件本身只做硬链接）。

**Q：媒体库里出现了重复的剧集目录（如 `示例综艺 (2025)` 和 `示例综艺 (2020)`）？**
插件优先复用媒体库已有目录并继承它的年份；没找到已有目录时才用源目录里的年份。
出现重复说明剧名没对上，加一条剧名映射，让左边解析出的名字和媒体库目录完全一致。

**Q：加更文件没被处理？**
同时检查三件事：① 文件名含「加更」；② 含 `.Plus` 或 `.Extra`；③ 所在季目录名含 `.S<数字>.`。
三者缺一都不会动。命名里只有 `加更`、没有 `Plus/Extra` 的文件会被刻意忽略（可能是花絮）。

**Q：集号和我预期的不一样？**
`yy` 是「该季已有最大集号 + 序号」，不是期号。加更永远排在正片之后，避免占用正片集号。
如果正片后续又更新到更高集号，加更不会自动后移——需要删掉旧的加更链接再跑一次（源文件不受影响）。

**Q：Emby 里标题还是显示 TMDB 的集标题？**
`第 ZZ 集加更` 写在文件名里，主要用于人工识别和媒体库排序；最终显示标题仍以刮削源为准。
不想被 TMDB 覆盖的话，可以在媒体库里把该集锁定为「使用文件信息」。

**Q：能处理电影、短剧、动漫的特别篇吗？**
不能。插件只针对「按季分目录的综艺」这一种结构，其他类型不做处理。

**Q：会不会误删我的文件？**
不会。插件对源目录只有「读取」和「硬链接」两种操作，没有任何删除、移动、重命名。

## 9. 限制

- 仅支持硬链接，**要求源目录与媒体库目录在同一文件系统**；
- 仅识别名为 `*加更*` 且带 `.Plus` / `.Extra` 的文件，其它命名规则不处理；
- 季号来自源目录名，正片集号来自目标季目录里已有的文件；
- 期号取自源文件的 `SxxEyy` 中的 `yy`，源文件期号不规范时 `ZZ` 会跟着错；
- 定时任务由插件自己的调度器运行，重启 MoviePilot 后需要插件处于启用状态才会重新挂上。

---

## 10. 卸载与回滚

- 直接停用插件，定时任务即停止；已生成的硬链接仍在媒体库里，可按需删除（**删除链接不影响源文件**）；
- 要彻底还原，把生成的 `* - SxxEyy - 第 ZZ 集加更.*` 文件删掉即可，源目录自始至终未被改动。
